# Test quarantine register

This register is the canonical inventory of the narrowly approved non-gating test scenarios. The assertions remain in their source files. Every scenario has an exact-name diagnostic run; setup, compilation, selection, and required infrastructure remain blocking. The ordinary test and coverage gates remain hard failures for all other tests.

The two differential scenarios use the fake broker and have no Apache Pulsar dependency. The e2e scenario runs only on Pulsar 5.0.0 through the existing reusable Pulsar workflow, on pull requests, pushes to `main`, and manual CI dispatch. It is not part of the 4.0.14 nightly. Its diagnostic is non-gating only after the test reaches `QUARANTINE_PULSAR_READY`; startup failure stays blocking.

The `differential quarantine diagnostics` job executes each differential test independently after blocking compilation and exact-selection checks. `e2e quarantine diagnostics (Pulsar 5.0.0)` reuses the existing Docker/image/toolchain preflight and blocks on target compilation and exact selection; only the exact scenario's post-readiness test result is non-gating. Each invocation records its result in the GitHub step summary.

The coverage command retains test execution, infrastructure, report collection, and uncovered-line verdicts separately. After a test command exits nonzero, it still attempts a fresh report for each isolated domain, evaluates every valid report, publishes only valid reports from this invocation, and exits nonzero. Failed collection removes stale LCOV diagnostics and cannot turn an old report into current evidence. The ADR-0121 100%-on-the-diff threshold and both evidence domains remain unchanged.
